# Compiled API v1 Contracts (`contracts/v1/`)

This directory contains the machine-readable JSON Schema (Draft-07) specifications emitted from the authoritative Zod contracts in `lib/contracts/v1/**`.

> **DO NOT EDIT BY HAND**  
> All JSON files in this directory are automatically generated by running `npm run emit-contracts`. Manual changes will be overwritten and will fail CI verification (`git diff --exit-code contracts/v1/`).

---

## 1. Purpose & Mobile Contract Boundary

The web backend (`temprfit-web`) and mobile application (`temprfit-mobile`) share **no code, no shared npm/Dart package, and no monorepo tooling**. The JSON schemas in this directory define the exact wire protocol between them.

- **Mobile Client Model Generation:** Flutter/Dart data transfer models (`temprfit-mobile/lib/data/models/**`) are generated or verified against these schemas (e.g., using `quicktype` or custom Freezed code generators).
- **Parity Verification:** Test suites in both repositories validate payloads against these definitions to guarantee zero contract drift.

---

## 2. Mobile-Facing Versioning Rule

> **CRITICAL RULE:** Any change to a contract schema requires an explicit bump to its `version` field in `lib/contracts/v1/<name>.js`.

Mobile apps cannot be force-reloaded like web pages; users run older app builds for weeks or months. To prevent runtime serialization crashes on mobile devices, follow these strict rules:

### A. Non-Breaking Changes (Minor / Patch Bump)
- **What qualifies:** Adding a new optional field, adding a new nullable property, or relaxing a constraint.
- **Action:** Bump minor or patch version (e.g., `1.0.0` -> `1.1.0`).
- **Mobile handling:** Mobile clients must ignore unknown fields and treat newly added optional fields as nullable with defaults.

### B. Breaking Changes (Major Version Bump)
- **What qualifies:** Removing an existing field, renaming a field, changing the data type of an existing field, or converting an optional field to required.
- **Action:**
  1. Major version bump (e.g., `1.0.0` -> `2.0.0`).
  2. **Do NOT break deployed mobile clients:** Maintain backwards-compatible response transformers on `/api/v1/**`, or introduce the breaking contract under a new route path (e.g., `/api/v2/**`).
  3. If an older mobile version is completely unsupported, enforce deprecation through the mobile `/api/app/min-version` gate.

## 3. Workflow for Developers

1. Define or edit the Zod schema in `temprfit-web/lib/contracts/v1/<name>.js`.
2. Bump the `version` field in `contractMetadata`.
3. Run schema emission:
   ```bash
   npm run emit-contracts
   ```
4. Verify no uncommitted contract drift:
   ```bash
   npm run check:contracts
   ```
5. Commit both the `lib/contracts/v1/` source and the corresponding `contracts/v1/*.json` output.
